# 인터랙션 기획안 (Interaction Design Plan)

> `01-curriculum-plan.md`의 슬라이드에 배치된 인터랙션들의 상세 설계입니다. 각 인터랙션은 아래 8개 항목을 모두 정의합니다.
> 1) 설명 개념 2) 필요 이유 3) 강사 조작 버튼 4) 화면 변화 5) 참석자가 얻는 이해 6) 예상 소요시간 7) 실제 AI API 필요 여부 8) 사전 제작 데이터만으로 구현 가능 여부
>
> **우선 구현 3종**(본 PR에서 실제 코드로 구현): INT-00, INT-03, INT-06. 나머지는 설계만 확정하고 추후 구현합니다.

## INT-00. 전역 용어 도움말 (Glossary Mode) — ✅ 구현됨

1. **개념**: LLM, Token, RAG 등 전문 용어 전체
2. **필요 이유**: 초보자는 용어 설명이 필요하고, 경험자는 반복 설명이 불필요함 — 두 집단을 한 화면에서 동시에 만족시키려면 온디맨드 설명이 유일한 방법
3. **강사 조작**: 상단 바의 `용어 도움말 ON/OFF` 토글 1개
4. **화면 변화**: ON 시 전문 용어에 점선 밑줄 표시 → 클릭하면 정의/비유/업무사례 팝오버 → 슬라이드 하단에 현재 화면에 등장한 용어만 모은 주석 패널 표시. OFF 시 밑줄·패널 모두 숨김
5. **참석자 이해**: "모르면 즉시 찾아볼 수 있다"는 안전감 + 같은 용어를 어디서 봐도 같은 정의라는 신뢰
6. **예상 소요시간**: 강의 흐름 추가 없음(상시 대기 기능), 팝오버 확인 시 개별 5~10초
7. **실제 AI API 필요**: 불필요
8. **사전 제작 데이터만으로 구현 가능**: 가능 — 중앙 용어 데이터 파일(`src/content/glossary.ts`) 1개로 전체 사이트 커버

## INT-01. AI 발전 타임라인 확대뷰

1. **개념**: AI 역사(1950s~2026) 속 주요 변곡점
2. **필요 이유**: 70년을 한 문장으로 설명하면 안 남고, 모든 사건을 다 말하면 20분을 넘김 — 강사가 필요한 노드만 선택적으로 확대 설명해야 함
3. **강사 조작**: 타임라인 바 위 노드 클릭(확대 카드 열기/닫기), `처음부터` 리셋
4. **화면 변화**: 클릭한 노드가 확대되며 정의 카드가 펼쳐지고, 나머지 노드는 축소·흐림 처리
5. **참석자 이해**: 최근 5년의 변화 속도가 이전 수십 년과 질적으로 다르다는 감각
6. **예상 소요시간**: 3분(노드 2~3개 선택 설명)
7. **실제 AI API 필요**: 불필요
8. **사전 제작 데이터만으로 구현 가능**: 가능 — 연표 JSON 1개

---

## INT-02. AI·ML·DL·생성형AI 관계도

1. **개념**: AI ⊃ ML ⊃ DL ⊃ 생성형AI 포함 관계
2. **필요 이유**: 네 용어가 늘 같이 언급되지만 포함관계를 말로만 설명하면 금방 헷갈림
3. **강사 조작**: 동심원 영역 클릭(해당 영역 확대+정의 표시), 전체 보기로 복귀
4. **화면 변화**: 클릭한 원이 확대되고 바깥 원은 음영 처리, 정의·대표 사례 텍스트 등장
5. **참석자 이해**: 네 용어가 서로 배타적 개념이 아니라 포함관계라는 구조적 이해
6. **예상 소요시간**: 2분
7. **실제 AI API 필요**: 불필요
8. **사전 제작 데이터만으로 구현 가능**: 가능 — SVG 좌표 + 정의 텍스트 고정값

## INT-03. Chatbot vs AI Agent 인터랙티브 비교 — ✅ 구현됨 (핵심 콘텐츠)

1. **개념**: 동일 업무("조직문화 행사 준비")를 Chatbot 방식과 AI Agent 방식이 각각 어떻게 처리하는지의 개념적 차이
2. **필요 이유**: 두 방식의 차이는 "출력" 자체가 아니라 "과정과 사용자 개입 지점"에 있음 — 말로는 전달이 안 되고, 과정을 단계별로 "보여줘야" 함
3. **강사 조작**: 모드 전환(Chatbot/Agent), 다음 단계, 이전 단계, 자동 재생, 일시정지, 초기화, 전체 과정 비교 보기
4. **화면 변화**: 선택 모드의 단계가 노드로 순차 등장하고 연결선이 그려짐. 자동재생 시 일정 간격으로 다음 단계 진행. 비교 보기에서는 두 모드의 단계가 좌우로 나란히 표시
5. **참석자 이해**: 기술적으로 챗봇도 도구를 쓸 수 있으므로 특정 제품의 이분법이 아니라, "사용자가 매 단계 개입하는 정도"가 핵심 차이라는 개념적 구분
6. **예상 소요시간**: PART1 예고판 포함 8분(PART1 5분 + PART4 본편 3분 재설명)
7. **실제 AI API 필요**: 불필요(사전 정의된 단계 스크립트 재생)
8. **사전 제작 데이터만으로 구현 가능**: 가능 — 모드별 단계 배열(JSON)

## INT-04. LLM 토큰 생성 시뮬레이터

1. **개념**: LLM이 다음 토큰을 선택하는 과정(확률 분포 기반 선택)
2. **필요 이유**: "다음 단어를 예측한다"는 말은 추상적 — 실제로 후보들 사이에서 확률적으로 고른다는 과정을 직접 눌러봐야 체감됨
3. **강사 조작**: 다음 토큰 생성, 후보 비교 보기, 처음부터 다시, 결정적 선택/확률적 선택 모드 전환
4. **화면 변화**: "오늘 점심 메뉴는" 뒤에 후보 토큰과 가상 확률 막대가 나타나고, 클릭 시 선택된 토큰이 문장에 이어붙여짐
5. **참석자 이해**: ①토큰이 띄어쓰기 단위와 다를 수 있다 ②같은 입력도 확률적 선택이면 매번 다른 문장이 나올 수 있다
6. **예상 소요시간**: 4분
7. **실제 AI API 필요**: 불필요 — 반드시 "교육용 가상 확률치, 실제 모델 수치 아님" 명시
8. **사전 제작 데이터만으로 구현 가능**: 가능 — 토큰 후보 트리(JSON) 사전 설계

---

## INT-05. RAG 시뮬레이터

1. **개념**: 질문 → 문서 검색 → 근거 추출 → 답변 생성 → 출처 확인의 RAG 파이프라인
2. **필요 이유**: RAG를 "검색해서 답한다"로만 설명하면 할루시네이션이 왜 줄어드는지, 왜 완전히 없어지지는 않는지가 전달되지 않음
3. **강사 조작**: 단계 재생(질문→검색→추출→생성→출처), 시나리오 전환(정상 답변 / 검색 실패·근거 부족 답변), 초기화
4. **화면 변화**: 질문이 문서 저장소로 이동하는 애니메이션 → 관련 문서 하이라이트 → 답변 생성 시 출처 배지 부착. 실패 시나리오에서는 "관련 문서 없음" 경고와 함께 불확실한 답변이 표시됨
5. **참석자 이해**: RAG는 할루시네이션을 줄이는 구조이지 완전히 없애는 보장은 아니라는 균형잡힌 이해
6. **예상 소요시간**: 4분
7. **실제 AI API 필요**: 불필요
8. **사전 제작 데이터만으로 구현 가능**: 가능 — 가상 사내 규정 문서 세트 + 정답/실패 시나리오 2종

---

## INT-06. 프롬프트 개선 시뮬레이터 — ✅ 구현됨 (핵심 콘텐츠)

1. **개념**: 목적·배경·독자·제약·출력형식·검증기준을 더할수록 프롬프트와 결과물 품질이 달라짐
2. **필요 이유**: "프롬프트를 구체적으로 써라"는 조언은 추상적 — 동일 주제에 요소를 하나씩 더했을 때 결과가 바뀌는 과정을 직접 봐야 체감됨
3. **강사 조작**: 요소 추가(목적/배경/독자/제약/출력형식/검증기준) 토글, 비교 모드(처음 vs 최종), 초기화
4. **화면 변화**: 좌측 프롬프트 편집 영역에 선택한 요소가 누적 삽입(새 부분 하이라이트), 우측 미리보기에 해당 조합에 대응하는 사전 작성 예시 결과물이 교체, 하단에 개선 포인트 해설 갱신
5. **참석자 이해**: 좋은 프롬프트는 "길게 쓰기"가 아니라 "빠진 요소를 채우기"라는 이해
6. **예상 소요시간**: PART3 본편 6분 + Playground 자유체험(시간 제한 없음)
7. **실제 AI API 필요**: 불필요 — 모든 결과물은 사전 작성된 예시
8. **사전 제작 데이터만으로 구현 가능**: 가능 — 요소 조합별 예시 결과물 매핑(최대 2^6 중 대표 조합만 선별 제작)

## INT-07. AI 답변 검증 게임

1. **개념**: AI 답변 속 확인된 사실 / 오류 / 근거 부족 / 허구 출처를 구분하는 검증 습관
2. **필요 이유**: "AI를 무조건 믿지 말라"는 당부만으로는 행동이 바뀌지 않음 — 실제로 속아보는 경험이 필요
3. **강사 조작**: 문장 클릭(상태 공개), 전체 정답 공개, 다른 답변 샘플로 전환
4. **화면 변화**: 클릭한 문장에 `[확인된 사실]/[오류]/[근거 부족]` 배지가 표시되고 정확한 설명·검증 방법이 펼쳐짐
5. **참석자 이해**: 그럴듯한 문장도 틀릴 수 있으며, 검증 방법(원문 대조, 출처 확인, 수치 재계산)이 구체적으로 존재한다는 이해
6. **예상 소요시간**: 5분
7. **실제 AI API 필요**: 불필요
8. **사전 제작 데이터만으로 구현 가능**: 가능 — 교육용 혼합 답변 텍스트 + 문장별 정답 라벨

---

## INT-08. Agent Workflow 단계도

1. **개념**: 목표 설정 → 계획 수립 → 도구 사용 → 중간 검토 → 결과 생성 → 사람 승인의 Agent 워크플로
2. **필요 이유**: INT-03에서 본 개념을 실제 업무 자동화 사례(반복 업무)에 적용해 "승인 단계가 왜 끝까지 남는지" 강조해야 함
3. **강사 조작**: 단계 재생(다음/이전), 승인 단계에서 "승인/반려" 분기 보여주기, 초기화
4. **화면 변화**: 단계별 노드가 순서대로 강조되며 승인 단계에서 두 분기(승인 시 종료 / 반려 시 재계획으로 되돌아가는 화살표)가 함께 표시
5. **참석자 이해**: 자동화되어도 최종 책임과 승인은 사람에게 남는다는 구조적 이해
6. **예상 소요시간**: 5분
7. **실제 AI API 필요**: 불필요
8. **사전 제작 데이터만으로 구현 가능**: 가능 — INT-03과 데이터 구조 재사용

---

## INT-09. 제조업 업무 시뮬레이션 (규칙 기반, 교육용)

1. **개념**: 장비 가동시간·작업 우선순위·납기·점검일정이 얽힌 생산 일정에서 발생하는 충돌
2. **필요 이유**: 제조업 참석자에게는 추상적 AI 개념보다 "내 업무에 대응하는 장면"이 있어야 체감도가 높음
3. **강사 조작**: 조건 변경 슬라이더/토글(우선순위 변경, 점검 일정 삽입), 충돌 하이라이트 보기, AI 보조 제안 단계별 보기, 초기화
4. **화면 변화**: 간트형 타임라인에서 조건 변경 시 충돌 구간이 빨간색으로 하이라이트되고, 이어서 "AI 보조 제안" 단계(재배치 제안→사람 확인)가 순차 표시
5. **참석자 이해**: 이 기능은 실제 생산 최적화 엔진이 아니라 교육용 규칙 기반 시뮬레이션이라는 점을 명확히 인지하면서도, AI 보조 의사결정의 패턴은 체감
6. **예상 소요시간**: 4분
7. **실제 AI API 필요**: 불필요
8. **사전 제작 데이터만으로 구현 가능**: 가능 — 가상 생산일정 데이터셋(실제 공정/설비/회사 정보 미사용)
